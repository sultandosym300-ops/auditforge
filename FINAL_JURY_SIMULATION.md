## Что проверили

Исходная линия от `a46d7551249654cd8d27536e95d9c8fd42b76271` повторилась на Python 3.11.1. Прошли 66 тестов, 20 финансовых эпизодов, 20 пар, 64 дополнительных seed и 80 прогонов политик. Для сравнения доступен [контейнерный прогон 1.1.1](https://github.com/sultandosym300-ops/geneziz/actions/runs/44585274002).

В 1.1.2 прошёл 81 тест, включая 15 новых. Независимый аудитор считает округление целыми операциями над рациональными числами, восстанавливает расхождения по публичным документам и только затем сравнивает выводы с эталоном и причинным журналом. Методика и результаты доступны в [массовом прогоне](reports/financial-audit.json), [дополнительном наборе](reports/financial-holdout.json) и [основном отчёте](reports/verification.json).

Mutation testing изолировал десять искусственных дефектов в временных копиях. Тесты обнаружили 10/10, включая ошибочное округление, ошибку паросочетания, раскрытие закрытого поля, включённую правую границу периода и лишний шаг. Отчёт хранит имена сработавших тестов и хеши проверенных исходников. [Результаты мутаций](reports/mutation-audit.json)

Профиль стресс-эпизода составил 952 строки проводок, 473 документа, 12 ошибок и 33 шага. Reset и политика заняли около 0,17 с вместе. Одно сопоставление занимало в среднем около 0,41 мс на машине проверки. Локальные выделения Python измерены через `tracemalloc`. Контейнерный workflow отдельно печатает пиковую память cgroup, проверяет лимиты и фактическую конфигурацию контейнера политики. ## Исправленные дефекты

| Дефект | Причина | Исправление |
|---|---|---|
| Четыре значения неверного типа проходили в `reset` | Прокси заменял любой ложный аргумент пустым объектом | Исходное значение передаётся до валидатора генератора |
| Ссылка на счёт могла вернуть случайную проводку | Журнал разрешал искать по неуникальным ссылкам | Журнал адресуется собственным ID строки |
| Прямой вызов `Session.reset` отдавал изменяемое состояние | В ответ попадали ссылки на manifest и policy | Сброс возвращает копии |
| Некорректное количество в строке счёта проходило валидацию | Проверялась только сумма строк | Проверяется произведение количества на цену |
| Ссылка на обычный платёж засчитывалась как доказательство возврата | Проверялась видимость ссылки, без проверки типа и обязательства | Валидатор требует отрицательный возврат по тому же счёту |

Дополнительно генератор получил выбор месяца и сценарий с корректными платежами на обеих сторонах закрытия. Обычные параметры сохранили последовательность генерации и контрольную проводку `seed=21`.

## Три примера для выступления

1. **Одна минимальная единица.** На `seed=21` проводка меняется с 499979 до 249724. Правильное отклонение 250255 проходит, 250254 отвергается. Для валютного платежа требуется публичная запись курса.
2. **Защита награды.** На основном наборе средний F1 политики сверки и oracle равен 1, «пометить всё» получает 0. Сверка сохраняет результат после замены ID, имён и перестановки строк. Для неё достаточно полных публичных записей, поэтому F1 = 1 говорит о разрешимости учебной задачи.
3. **Новый seed.** Штатная сверка с `seed=1231263901` прошла за 11 шагов и дала P = R = F1 = 1, reward = 0,98. Повторите доверенный демонстрационный запуск командой `python -m auditforge.agent_runner --trusted-native --seed 1231263901`.

## Как повторить

```sh
python -m auditforge.verify --seed 807102432503
```

Python 3.11 и стандартная библиотека достаточны. Команда возвращает ненулевой код при провале, обновляет открытые примеры и отчёт и записывает эталон в отдельный игнорируемый каталог. В репозитории находятся 10 train, 10 dev и 30 обучающих траекторий. Проверка границ Docker выполняется отдельно на Linux с Docker. В браузере пользователю доступны данные его собственной учебной сессии. Для закрытого теста используйте непубличный высокоэнтропийный seed и контейнер политики.
