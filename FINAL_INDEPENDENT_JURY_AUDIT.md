# Проверка кандидата AuditForge 2.0

Кандидат добавляет сценарий «По обе стороны закрытия» в обычный reset и рабочую часть сайта на русском, английском и казахском. Для слепого эпизода используется `{"recognition_world":"blind"}`. Публичный интерфейс возвращает документы и записи через обычные пять действий.

Локальная реконструкция шкалы требует 20 контрактных проверок, 20 новых компаний, 20 проверок награды, 20 парных испытаний и пяти инженерных пунктов. Полный расширенный запуск выполняется командой ниже. Его JSON и таблицы сохраняются в указанной папке, а исторический отчёт 1.1.4 остаётся доступным.

```sh
python -m scripts.jury_gauntlet --seed 274887116039 --report-dir work/jury-v2
python -m scripts.world_comparison
python -m scripts.recognition_demo
```

96 регрессионных тестов проверяют основной контракт и новый сценарий. Мутационный набор включает 16 неисправностей. Во время разработки проверка хешей правильно отклонила запуск, в котором исходники менялись параллельно. Итоговый прогон выполняется на зафиксированных исходниках.

Сценарий проверяется действующим независимым финансовым аудитором с рациональной арифметикой. На основной и подтверждающей выборках проверены 512 новых компаний кандидата. Все расследования полной и специализированной политики достигли F1=1, собирая подтверждения только через публичные действия. Для четырёх состояний изолированный контейнер также запускает штатную политику.

Демо на seed 34815267 содержит 238 одинаковых проводок в двух книгах. Две встречные ошибки по 3 029,97 KZT дают нулевую разницу общей суммы расходов. Политика подтверждает обе за семь шагов. Удаление документа из первого ответа снижает F1 до 0,5. Браузерный Web Worker отдельно проверен в Chrome для четырёх состояний и слепого выбора, F1=1 в каждом.

В процессе проверки исправлены затенение флага сценария локальной переменной и побочный признак в сроке оплаты. Все счета теперь следуют согласованному правилу срока оплаты. Основная и дополнительная выборки повторены после исправления.

Контейнерный CI запускает испытания без сети, на двух CPU и с 4 GiB памяти. Он проверяет ограничения, размер поставки и передачу доказательств в отдельный контейнер политики. Результат конкретного релиза виден в GitHub Actions.

Основание принятия — измеримое снижение точности поверхностных классификаторов при сохранении разрешимости, бухгалтерской корректности и совместимости. Архитектурные альтернативы описаны в [исследовании](ARCHITECTURE_BREAKTHROUGH_RESEARCH.md), сравнение и интервалы — в [результатах](AUDITFORGE_114_VS_CANDIDATE.md).

Официальная оценка принадлежит жюри. Локальный максимум по опубликованной шкале не гарантирует победу. Новый контролируемый сценарий даёт воспроизводимую демонстрацию того, зачем аудитору сопоставлять конкретные документы, даже когда бухгалтерские итоги сходятся.
