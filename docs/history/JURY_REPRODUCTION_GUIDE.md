# Воспроизведение проверки AuditForge

Точный SHA рабочего ядра — caf98acaf0e5c5b1dd74d516325aaae18536a3ba, тег auditforge-2.0.1-control. Итоговый исследовательский выпуск сохраняет те же исходники auditforge. SHA полного архива записан Git в комментарии ZIP. В checkout точную ревизию показывает git rev-parse HEAD. Итоговый SHA выпуска также предоставлен вместе со ссылкой на финальный CI.

## Автономный запуск

Распакуйте сдаваемый архив, перейдите в каталог AuditForge и выполните с Python 3.11:

python -m scripts.ultimate_verify --seed 801973140685

На Windows используйте py -3.11 вместо python. Ядро и проверка используют стандартную библиотеку. Не нужны API-ключи, GPU, учётная запись разработчика или доступ к его файлам. Вход на веб-сайт не требуется. Команда создаёт отчёты и временные копии только внутри проекта.

Итоговая таблица — reports/ultimate-jury.json. Там отдельно хранятся 20 контрактных проверок, 20 компаний, 20 наградных проверок, 20 пар и пять инженерных пунктов. Дополнительные исследования не увеличивают официальный максимум 100. В work/ultimate-legacy остаются результаты предыдущего расширенного набора.

## Отдельные исследования

python -m scripts.ultimate_matrix

python -m scripts.ultimate_evidence

python -m scripts.ultimate_adaptive

python -m scripts.ultimate_contract

Все параметры и метрики находятся в reports/ultimate-*.json. Можно изменить корневой seed единой команды для нового набора компаний. Adaptive использует отдельный записанный корень и train/dev/test, чтобы не менять обученный выбор после просмотра holdout. Его независимый повтор с иным seed задаётся собственной CLI-командой.

## Контейнер и ресурсы

docker build -t auditforge-evaluator:2.0.1 .

docker run --rm --network none --cpus 2 --memory 4g --mount type=bind,source=ABSOLUTE_PROJECT_PATH,target=/submission -w /submission auditforge-evaluator:2.0.1 python -m scripts.ultimate_verify

Подставьте абсолютную папку проекта вместо ABSOLUTE_PROJECT_PATH. Базовый образ должен быть доступен до отключения сети. Политики ограничены 100 шагами и 60 секундами. Workflow отдельно проверяет cgroup, объём поставки менее 1 GB, отсутствие сети, прав записи в контейнере политики и доступа к приватным файлам. Контейнерные команды следует брать из .github/workflows/verify.yml для точного повторения релиза.

## Контроль архива

Проверьте комментарий ZIP стандартной библиотекой Python с помощью zipfile.ZipFile(path).comment.decode(). Он должен совпасть с предоставленным финальным SHA. Затем распакуйте архив в новую папку и запустите единую команду. Архив не содержит приватных evaluator_private, локальных work, node_modules и привязки hosting. Проверка может заново создать evaluator_private для доверенного оценщика; эти данные не передаются политике.

Результаты измеряют локальную реконструкцию публичных правил. Закрытые проверки организаторов недоступны. Для защиты продемонстрируйте реальные документы и последствия удаления доказательства, а затем независимые результаты и ограничения.
